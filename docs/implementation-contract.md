# Mangekyo 实现契约

2026-11-16｜给实现者与派发者的共同约束。产品结果以 [PRD](PRD.md) 为准，内核语义以 [kernel-design](kernel-design.md) 为准。本文把既有要求变成任务边界和验收规则，不增加产品能力。

## 1. 模块只拥有领域定义

- 新能力必须落入事实类型、命令、推导器或块。槽位声明是推导器定义的一部分。需要第五类构件时停止实现并报告。
- 一个模块只拥有自己定义的事实。其他模块只能经公开事实类型、槽位类型和内核上下文协作，不能读取或修改其实现。
- 包导出和类型检查必须使越界导入无法编译。`@mangekyo/kernel` 是模块唯一可导入的声明包；`Db`、SQL、加载器与执行适配器只供内核与执行环境，不是模块的依赖，也不从该声明包导出。模块的公开入口不能暴露 `Db`、SQL、环境变量、网络、模型 SDK、队列库或 agent SDK。模块消费方的编译边界测试必须使用实际安装包，不能靠仓库内路径映射假装验证 exports。
- 模块不建表、不写迁移、不注册路由或工具。内核从命令和槽位定义生成外部入口。
- 单元 2 的目录加载器只加载声明，不是完整模块沙箱。加载前的静态依赖检查与 gather 的进程隔离由后续结构检查、Python worker 和模型边界单元共同落实；在它们完成前不得声称模块运行时已经不能访问网络、环境变量或任意包。

## 2. 每类状态只有一个写入者

- 命令是事实的唯一写入入口。内核执行命令、修订、用途、提议和撤销。界面和会话不能另写事实。
- 内核是推导状态的唯一写入者。推导器返回候选，不能直接接受、传播、采纳或调度自己的结果。
- Temporal 是唯一执行恢复权威。业务工作、会话问答和审计不是第二份 claim/租约/步骤游标；工作意图经同事务 outbox 和幂等 relay 交接，禁止同时引入 pg-boss 或另一循环 checkpointer。
- 界面只发命令、读槽位和渲染块。界面不能重算判分、掌握度、安排或证据权重。
- 每个任务声明自己拥有的文件。契约层和填充层分开交付，同一工作树只有一个代码写入者。

## 3. 类型表达合法状态

- 用判别联合表达事实写入、推导结果、工作状态、提议和错误。不要用一组必须靠注释才能正确组合的布尔值和可选字段。
- `unknown` 是推导的合法值。`pending` 表示等待计算，`stale` 表示输入已失效，`behind` 表示输入有新增，`error` 表示执行失败。它们不能互相冒充。
- 在命令、IPC、数据库和配置边界校验输入并生成领域类型。模块内部不信任外部 JSON，不通过类型断言绕过校验。
- 学习者、事实、命令、推导、槽位和效果标识各有类型。每次内核读写都显式携带学习者作用域。

## 4. 权限和效果留在内核边界

- `gather` 经内核上下文读取，内核记录实际输入清单并检查用途。`derive` 只接收固定、可序列化的输入包，不能读取环境或再次取数。
- 模型调用、代码执行和其他外部效果经内核提供的受限能力执行。模块不能直接取得 provider 凭据。
- 外部效果在调用前登记稳定身份。已完成的结果可复用，结果未知时必须可核对，不能因本地重试而宣称 provider 保证不重复扣费。
- 学习者的破坏性操作由命令定义声明。AI 发出时生成提议，学习者确认后才执行。
- 永久删除按 ADR-0008 是明确、不可 undo 的存储销毁例外；临时使用、命令输入/回执、效果/日志、Temporal 载荷、对象历史和离线副本都按产品规格 D06 处理。旧命令仅能返回已删除状态，不因回执重放恢复已删除正文。仅保存不为危机扫描例外开放。

## 5. 任务必须自带行为证据

测试预算：测试代码占全部代码不超过 10%，统一统计 TS/JS、Python 及实际引入的其他语言非空代码行，测试、夹具、测试基础设施和生成器内嵌测试样例均计入分子；文档、证据、依赖与构建产物不计入。不得压行、改名、隐藏临时测试或扩充生产代码规避预算。`pnpm check:test-budget` 已接 `test` / `test:pg`，但当前脚本仅覆盖 TS/JS，**尚不满足跨语言目标口径**；单元 6 必须在引入 Python 代码前补齐。保留核心不变量，日常声明和可逆工具行为用类型、样例及实际验收证明。

- 派发单位是一个事实类型、命令、推导器或块及其样例。任务卡写明公开类型、拥有文件、正例、反例和验收方法。
- 推导器样例包含具体输入和预期输出，至少一个反例能区分正确与错误行为。不得用空样例或实现重新计算的答案验收。
- 内核测试调用公开命令和读取接口，断言规格规定的状态与可见结果。并发和锁行为必须在真实 PostgreSQL 上验证。
- 真实场景在对应界面上操作并保存结果。编译、固定样例、CLI、PGlite 或 agent 自报分别只证明自己的范围。
- 交付记录写明实际运行的命令、结果、依赖版本和未验证项。失败记录不得被后续成功演示覆盖。

## 6. 遇到这些信号先停

- 填充任务需要修改公共类型、数据库、路由表或另一个模块才能交付。
- 同一规则出现在两个模块，或调用方需要知道被调用方的内部状态才能完成操作。
- 新任务必须阅读整个仓库才能开始，或一个改动无法由任务卡中的样例和不变量判定对错。
- 为满足局部任务而增加兼容分支、隐式重试、第二写入路径或新的全局登记表。
- 加入新执行环境或适配器需要修改模块代码。此时按 PRD §11 检查模型，而不是继续补例外。
