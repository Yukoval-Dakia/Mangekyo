# Mangekyo 功能与目标承接盘点

历史状态：本文保留2026-11-15盘点时的建议、部分与条件标签；2026-11-17 owner授权后的现行裁决见 [产品规格](product-spec.md) 与 [73项功能去向](feature-disposition.md)。本文不再作为范围待决定的依据，也不表示原能力已运行。

2026-11-15。盘点旧 Loom / the-learning-project 的功能知识，对照现行 [PRD](PRD.md)。本报告记录发现和建议，不修改 PRD，不给旧实现增加兼容承诺，也不把旧工单转成新 BACKLOG。

## 结论

**七个核心目标已经带过来，具体学习旅程仍有缺口。** 新版的记录、画像、教研、语境、供给、分寸、算数，与旧七支柱同源；更正传播、独立作答证据、提前备课、未知、离线与多设备，在新 PRD 中比许多旧文档更清楚。没有理由为旧模块、队列、模型框架或数据库结构保留兼容层。

最值得 owner 明确取舍的是：

1. **纸上学习闭环**：打印安排里的卷子，拍回后对回原题和原任务，不重复收题或计证据；长材料不能截断。
2. **Backtrace**：从这次错误追溯本人以前具体的相似错法与成功解法，跨章节也能找到，并能打开真实作答。
3. **活笔记与共同编辑**：学习后持续演化笔记，保留本人修改、草稿和 AI 改动历史；不是只有“生成一篇笔记”。
4. **学习方法与帮助效果**：渐隐、自我解释、辨析、先试再讲；帮助备好了、看过了、当时做完了，与之后独立会了是不同的事。
5. **目标与误解的生命周期**：达成、停滞、改善、复发、退役；不让已完成目标和过期弱点永远拉着安排走。
6. **数据自主的完整语义**：导出、删除、单轮临时使用、外部搜索不带出本人原文，不能全由“用途”二字代替。
7. **低打扰与控制**：提议负担、可处理的失败、实际生效的模型选择；不要把教研内部管理交给学习者。

这些能力在现有事实、命令、推导器、块的表达范围内没有显示出必须引入第四种数据的反例。本次没有实现验证，不能据此证明内核已能承载全部细节。

## 证据与读法

来源详见 [来源与证据边界](feature-sweep-sources.md)。文档代号 D01–D12、源码代号 C01–C18 指该文的相应条目，Linear 编号可在其工单表直接打开。表中 `§3.9` 等写法表示 PRD §3 的第 9 条承诺，`D01:62` 表示 D01 文件第 62 行。

- **覆盖**：新版已承诺相应用户结果；不表示已经实现。
- **部分**：新版有总目标，但缺少旧需求中可观察的行为或完整闭环。
- **未表达**：新版没有足以验收该功能的文字；不据此推断 owner 已决定放弃。
- **不继承**：新版明确排除，或只是旧实现/旧迁移义务。
- **条件项**：旧材料仅为建议、理念探索、远期或需求触发项，不自动升级为必做。

旧证据分为文档原文、工单正文/讨论、静态源码三种。**本次没有运行旧产品，也没有证明任何学习效果。** 全量 Linear 索引已分页取尽，但只有 36 张正文与 4 张票的评论被深入核读；不是全库逐票审计。

## 明确不随功能一起搬的东西

- **代码和历史存量迁移。** 用户本次只授权功能与目标盘点；没有复制旧代码，也没有导入旧数据库或执行旧数据重放。
- **旧技术选型。** TanStack Start/Pi/Drizzle/DBOS 迁移、Mem0、Rust 同构核和旧 provider 绑定是历史背景。新 PRD 的 TypeScript、Python 推导器、单 PostgreSQL 与可替换 SDK 另有依据。
- **旧机制作为义务。** 固定角色数、教研白板、定时例会、AI 审 AI、准入多层门、某个锁顺序、五个笔记触发器、随机抽样概率及测试比例，不因旧票存在就必须继承。必要的产品结果已在矩阵中拆开。
- **旧命名与导航。** Loom、Copilot、Dreaming、旧页面路径、artifact 枚举和固定 UI 风格不成为新产品契约；共享工具、可恢复对话、提前备课、可读材料等价值要重新表达。
- **未验证的数字。** 旧阈值、延迟估计、成本预算和“连续五次即会了”等只作为历史验收样例。本次没有证明这些数字符合学习规律，也没有重测新版性能目标。
