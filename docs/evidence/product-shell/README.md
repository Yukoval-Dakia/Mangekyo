# 产品入口与流式对话验收

2026-11-18，本机 Chrome 连接独立的 Web 进程，Temporal Worker 在另一个进程，二者共享专用 PostgreSQL schema。使用合成材料和测试提问。界面为桌面侧栏和移动端底部导航，均包含今天、材料、同伴、我。[桌面截图](home.webp) · [390 像素截图](mobile.webp)

- 从全局「交入材料」保存一段课堂草稿，刷新详情页读回原文，在「材料」按个人材料筛选后找回。改写学习目标后在「今天」看见新目标。
- 从首页进入骑行讲义，把停车时间调为 20 分钟，看到移动均速仍为 20 公里/小时、全程均速变为 12 公里/小时。从讲义进入三题小卷，提交 18、14.4、15，刷新后读回逐题反馈。新一轮重做保留旧卷。
- 从骑行讲义的同伴入口提问，产品使用内置讲义的实际距离和时间。Chrome 的 Network 面板记录了 `GET /api/sessions/{id}/events` 上的 `progress` 与 `complete` 事件。本次真实网关返回了 40 种不同长度的中途正文，最后从数据库恢复整轮答复。合入后的复验同样收到了 40 个不同长度的中间正文、一次完成事件，页面刷新后仍可读回原答。[复验数据](companion-sse.json)配置为 `auto/deepseek-v4.1-flash`、`reasoning_effort: high`，网关报告 `group/auto-deepseek-v4-1-flash`。结构化诊断在模型输出通过校验后才显示题目。
- 在首页与材料之间切换、直接刷新子页、打开原示例课堂、手机窄屏导航均可工作。历史单元 40 的真实记录见[原验收](../unit40/README.md)。

合入后再次运行单元 40，使用固定的 DeepSeek 4.1 Flash 与 high 思考强度。两位学习者同答 45，Agent 均实际调阅了分段行程原作。看到独立列式后，它直接给出等距离往返的迁移题；看到例题后填答时，它先改变第二段的时长。后者解释自己始终直接平均速度后，Agent 转为要求先算总路程和总时间。[逐轮记录](first45.json) · [本机独立作答](http://127.0.0.1:4317/classroom/first45?session=C0E9BDF1182D433E6263E1AF90) · [本机例题后填答](http://127.0.0.1:4317/classroom/first45?session=50C1641A622C411911CDD81F36)
