# Mangekyo 工作单元

2026-11-17｜重新开发的执行入口。先读 [开发计划](development-plan.md)、[PRD](PRD.md)、[产品规格](product-spec.md)、[内核规格](kernel-design.md) 与 [实现契约](implementation-contract.md)；术语以 [GLOSSARY](../GLOSSARY.md) 为准。完整功能以 [功能去向](feature-disposition.md) 为索引，不能从旧工单直接开实现。

保留原 0–28 的编号身份，新增 29–40；按依赖执行，不按编号大小。`依赖` 表示完成后才能验收本单元，可提前准备不依赖它的设计和样例。D01–D10 范围均已裁决，单元 29–39 补齐功能，40 承接已采用的 Temporal。范围决定不表示这些单元已有实现。

每个条目是工作容器；派发时拆到一个事实类型、命令、推导器或块及其样例。标 **[契约]** 的内容先单独审查。本轮填充层基于已确定类型开工，内核公共接口在单元 25 通过前不宣称最终冻结。

## 当前合入顺序

| 批次 | 交付 |
| --- | --- |
| 模块边界 | 完成作答用时与原图裁剪。把 `runtime/` 纳入结构门禁。拍卷由 `capture` 拥有原件及结构化抽取，今日学习单由 `plan` 拥有目标、时间约束和锁定项。优先抽取现有命令、槽位与带见证的共用读口。 |
| 个性化 | 先合入自然对话调用 `save_memory`、结构化范围和可撤回回执。再用同一授权与证据契约接六类活动的异步抽取、正反核验及「我」的回读。见[全活动个性化抽取](design/agent-personalized-extraction.md)。 |
| 教学 | 交入原件后抽取多题、手写和订正，未知处一次询问。独立双解、正式判分与错因形成按知识点聚合的证据。独立 Python 推导器负责概率与不确定性，影子重放比较跨变式保持。今日学习单据时长、紧迫度与锁定项编排，空库和模型不可用时可开练。 |
| 后台与工具 | 在既有外发许可和额度内接前哨模型及重型备课。教材与题库经窄命令直接保存或就地显示建议。推进语义召回、真实曝光筛选、跨卷 Python 读与诊断镜头。见[前沿工具契约](design/frontier-agent-tools-spec.md)。 |

教学和后台分别交付可从正常入口完成的流程，共用命令、槽位和带见证读口。每批滚动合入，再以同一获准学习者联验跨线消费。

## M0：先让规格可实现

### 单元 0：规格消歧与两种内核设计

- **[契约] 依赖：** 无。规格消歧、两种设计和共同比较协议已完成，运行证据尚未产生。
- **产出：** 逐一解决开发计划 K01–K08，最小修订 kernel-design 与必要的术语；不改变产品结果的澄清由实现者完成，涉及 PRD 取舍才由 owner 决定。列出两种内核实现设计、相同输入样例、不变量、规模与比较指标。难反悔的选择记录 ADR。
- **验收：** 固定/跟随/截至引用、更正、等待、效果、撤销、旧值读取、时间与 ID 有无歧义输入输出；两个设计都能解释 §2.1–2.3 的完整数据流。若无法在四种模块构件内表达，按 PRD §11 报告，不开后续填充任务。

## M1：确定性链路，先证明接线

单元 0 的设计依据见 [manifest 直接查询](design/kernel-a-manifest-queries.md) 与 [独立依赖索引](design/kernel-b-dependency-index.md)。单元 0–2 已有实现证据；单元 3 的命令子系统已实现并验证已接路径（[记录](fleet-experiment.md)）；单元 25 才选择生产实现并冻结公共契约。

### 单元 1：workspace 与 Db 接口

- **[契约] 依赖：** 0。
- **产出：** pnpm workspace、TypeScript/Python 工具链入口；Db.query/tx 的 pg 与 PGlite 实现；每次读写的学习者作用域、学习者行锁与刻度。
- **验收：** 同一套事务/作用域样例在两实现通过；真实 PostgreSQL 验证锁竞争与回滚，不能用 PGlite 单连接证明并发。没有旧代码或存量迁移。

### 单元 2：schema、声明 API 与加载

- **[契约] 依赖：** 1。声明入口与内核/执行环境的 Db 入口已分离；schema 当前提供全新数据库的幂等建表，不是存量版本迁移器。
- **产出：** SQL 与版本化迁移入口（当前只有幂等建表，需补齐）；可导出/版本化的 schema 子集，事实、命令、槽位/推导器及 ctx/tools 类型；目录加载。槽位声明不增加第五类模块构件。对无法导出的 schema 报错，不能静默降级任意值。
- **验收：** 手写最小模块可加载；值可校验、包边界可编译；模块拿不到 Db、SDK、网络与环境变量。表结构服从单元 0 的消歧结果。

### 单元 3：命令执行

- **依赖：** 2；单元 2 的独立静态审查已完成，发现的加载索引与声明校验问题已修复。命令入口、事实修订、回执和必填事务 hook 已实现；生产传播/调度由单元 4 接线。
- **产出：** 唯一写入口、输入校验、幂等、回执及同事务登记传播/后续工作。
- **验收：** kernel §14 不变量 4；同 id 同内容只写一次，同 id 不同内容拒绝；两次真实同内容提交分别记录。传播未接全前只验已接路径，不宣称整链完成。

### 单元 4：生效、传播与需求调度

- **依赖：** 3、40。
- **产出：** accept、三种引用/range、stale/behind、需求登记与等待见证；通过 outbox 向 Temporal 交接，执行恢复不另造平行实现。
- **验收：** kernel §14 不变量 1、2、3、6、7；旧候选、更正竞态、旧 worker、范围内更正与范围外新增、等待登记竞态均覆盖；在 PostgreSQL 验证并发。过时旧值可读、不能支撑新生效。

### 单元 5：采纳、提议、撤销、用途与效果账本

- **依赖：** 4。
- **产出：** 稳定采纳身份与来源；sticky；破坏性提议、确认/拒绝；撤销；受用途限制的读取和证据回溯；稳定外部效果记录。
- **验收：** kernel §14 不变量 5、8、9、10；新建、批量写入及后续本人修改后的撤销符合单元 0 语义；用途收窄传播；done 不重复调用、started/unknown 可核对且不盲重付。永久删除不可 undo，完整销毁与防复活由 34 验收，不能沿普通撤销恢复已删正文。

### 单元 6：Python worker

- **依赖：** 2、4。
- **产出：** JSON 子进程宿主与纯计算协议、固定时钟样例、一个确定性记忆状态推导器；Python 纳入统一 10% 预算检查后再引入。算法由证据选择，不预先把简化公式当作有效。
- **验收：** TS/Python 共享样例输出一致、状态可序列化；崩溃/迟到结果服从 fencing，不让子进程绕过内核读取。

### 单元 8：第一条旅程的领域类型

- **[契约] 依赖：** 2、0；开工前独立设计评审。
- **产出：** capture/content/activity 的原件、题目、提交、帮助曝光、抽取/解答/判分槽位；以及该链所需 learner 声明、plan 目标/时间/锁定及相关槽位的最小公开类型。仅依据新规格和功能知识设计，不复制旧 schema。
- **验收：** 新写四页物理卷样例，分开原图、本人作答、红笔、未知及来源；按产品规格 D01/D03/D09 保护冻结题面、活动、提交、作答位与块身份；纸卷全链由 29 验收。评审缺口修正后再继续。

### 单元 24：掌握度与安排的确定性底座

- **[契约] 依赖：** 5、6、8。
- **产出：** range 取判分证据、Python 记忆状态、读取时随时间计算及不确定性；目标/时间约束下的确定性安排与今日视图；新需求出现时按需计算。
- **验收：** 更正传到掌握度和安排；帮助曝光使该提交仅为弱证据；未见过为未知。禁用模型后从已有可用材料得到可学安排，已有判断可读。空库无模型按已定 D08 在 36 提供真实内置活动，不用空卡片宣称兜底。

### 单元 9：确定性联调样例

- **依赖：** 24。
- **产出：** 仅限联调的固定抽取样例、精确选择题解答/判分与整链运行脚本，显式标识样例模式，不进入真实照片处理配置。
- **验收：** 固定输入从原件身份到安排跑通；注入更正后观察传播。此项不验照片识别、不验真实题目解答、不验 PRD §2.1。

### 单元 10：采纳与本人更正接线

- **依赖：** 9。
- **产出：** 抽取采纳题目/提交、本人更正命令、来源回溯与 sticky 接线。
- **验收：** 同一次重抽取不重复造题；更正保留旧修订、触发整链；再采纳转提议。此时用样例验协议，真实照片留给 23、25。

### 单元 11：定义生成的 CLI/HTTP 入口

- **依赖：** 10。
- **产出：** 命令与槽位的自动入口，含回执、状态及用途过滤的证据读取；没有模块手写路由表。
- **验收：** CLI/HTTP 执行同一命令返回相同语义；列举/读取槽位不泄露用途外信息；一条新命令无需另改路由/工具登记表。curl 只证明入口链路。

### 单元 22：第一条旅程的 Web 表面

首批已接通文字交入、刷新找回和目标设置，见[产品入口验收](evidence/product-shell/README.md)。四页照片交入与更正仍待验收。

- **依赖：** 11。
- **产出：** 手机收件、处理状态、材料与更正、今日安排的最小响应式表面；原件与大产物的对象存储适配，不把存储密钥交给模块。
- **验收：** 手机宽度实际交入四页，回执可见后可离开；读取原件、改作答、打开依据和今日材料；pending/unknown/error/stale/behind 分开。M1 用样例明确标识，M2 换真实抽取。

## M2：真实拍卷、更正与备课，再冻结接口

### 单元 17：模型网关与运行花费

- **[契约] 依赖：** 5。
- **产出：** 按单元 0 的执行边界提供任务档位、provider 配置、效果身份、实际模型/参数与成本记录；首次真实调用前核对当前 API，不把 SDK 给模块。
- **验收：** provider 失败和返回丢失可追踪；已完成效果复用，unknown 不盲重付；用途外原文不外发；会话和付费推导共用协议。完整模型/预算设置由 35、临时和删除载荷由 34 验收。

### 单元 23：真实抽取、解答、判分与错因

- **依赖：** 10、17、22。
- **产出：** 真实图片抽取、歧义澄清、独立方法解答及冲突时第三方法、结果/过程/错因推导；与联调固定抽取配置隔离。
- **验收：** PRD §2.1 的四页九题真实运行；未知只问一次且不先猜分；红笔按偏好处理；解答独立重做。失败可见且原件仍在，测量回执/处理目标，禁止固定输出冒充。

### 单元 21：内容检索与可用供给

- **依赖：** 23。
- **产出：** 现行 content 的题、笔记、知识点、语境读写与检索；按用途过滤索引；外找或生成材料并采纳来源；生成题独立解答一致性。
- **验收：** 已有题能读、改、找回；缺材料时交付真实可读笔记及可答变式；不一致不冒充可用。题目来源能打开；D02 的完整检索与历史诊断由 30 验收。

### 单元 12：会话宿主

按[主 Agent 记忆与工具升级](design/always-doing-and-agent-tools.md#3-主-agent-的记忆装配与写入边界)接入 Memory Gateway、意图预算与统一 Digest。工具 P1–P5 的切分与合入顺序见[开发与合入顺序](design/always-doing-and-agent-tools.md#5-开发与合入顺序)。

- **[契约] 依赖：** 11、17、40；开工前独立设计评审。
- **产出：** [会话宿主与学习工具](design/agent-harness-and-tools.md)定义完整会话的工作单、回合内输入、上下文、执行、交付及全部学习数据的读取与操作。由 [Pi Agent Core 与 Pi AI](adr/0010-pi-agent-sdk.md) 承接采样与工具批次，工具从命令和槽位生成。Temporal 唯一负责执行恢复。Python 能力经受控计算接入，按需评估 Pydantic AI。
- **验收：** 真实多步工具会话中断后由新 Worker 恢复，动态读取记入依据，已确认写入和收费结果复用。核对学生中途更正进入下一次采样，混合正文和回执重开可见，越界、撤权和外部效果未知有准确状态。工具从正常学生入口可查找并操作实际对象。[贯通验收](design/agent-harness-and-tools.md#6-实施衔接与验收)

### 单元 15：预测、对账与证据视图

- **依赖：** 12、24。
- **产出：** 可封存预测、真实后续提交对账、校准视图与“我”所需判断/证据槽位。
- **验收：** §2.5：先留预测，后独立提交，再展示预测与结果；未知有依据，可选探测活动真的可做。重放拟合不混入事前预测记录。

### 单元 14：常驻同伴与后台教研

按[Always-Doing 分层编排](design/always-doing-and-agent-tools.md)衔接已合入的 Temporal 协调器。首批先通 PG Todo、前哨派发、执行回执与真实学习产物，再接快照、轻量分诊和黄金样例。

按[四级自治与自研遗忘](design/autonomy-and-forgetting.md)交付「今天」与后台整理。日常结果直接可用，本人已编辑页的建议仅在该页呈现。真实后测与候选保持模型对照分别验收。

- **依赖：** 12、15、21、24。
- **产出：** [常驻教研](design/agent-harness-and-tools.md#5-常驻教研)定义独立于前台启动和恢复的后台同伴、可接续的研究线索、备好今天的工作单、材料齐备条件、预算和失败兜底。
- **验收：** 先放入获准回看的旧讲义和两份对讲义结论有区分力的作品，清空待办。所有前台关闭，常驻服务自行启动；验收期间没有学生请求、新材料或定时课。记录它实际调阅两份作品、据发现回看讲义并留下有原文依据的修订提议的时间。中断后台进程后由服务自行恢复，首次重开页面能读到此前已保存的结果。另验 §2.3 的备课交付、主动暂停、预算上限和无模型兜底。

### 单元 25：两种设计比较与真实旅程验收

- **依赖：** 14、22、23；实验方案来自 0。
- **产出：** 两种内核设计的可运行比较，及 §2.1–2.3 真实 Web 演示记录；选定实现的契约、性能与成本证据。
- **验收：** 同一数据、不变量与接近真实的规模下报告生效竞态、传播量/延迟、范围读取、锁等待、恢复及开发复杂度。真实照片→更正→备好今天完整走通，模型全挂仍可学；逐一记录未达性能目标。通过后才冻结公共契约并移除实验生产路径；不满足则回到原因所在契约，不加例外。

## M3：补齐现行场景与交付

### 单元 16：shadow 重放与方法替换
