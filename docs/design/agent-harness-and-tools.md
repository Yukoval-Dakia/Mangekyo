# Mangekyō 会话宿主与学习工具

2026-11-19 · 单元 12、14 的设计。产品范围以 [PRD](../PRD.md)、[产品规格](../product-spec.md) 和 [功能承接表](../feature-disposition.md) 为准。本文采用 [内核契约](../kernel-design.md)、[Temporal 决策](../adr/0007-temporal-durable-execution.md) 与[数据生命周期](../adr/0008-data-lifecycle-and-erasure.md)。实现与运行证据另记。[Codex、OpenCode 和 Pi 源码对照](agent-harness-source-review.md)

## 1. 设计决定

让同一个学习同伴能够做四类事：现场和学生一起学，读写完整学习工作区，交付可独立使用的学习产物，在学生离开后自行研究和接续。交互、备课、评阅和后台会话通过同一个会话宿主工作，各自带工作单、当前用途和预算。教材、题库、学情和计划归各自领域模块。

**Mangekyō 定义一轮如何接收输入、什么可以发送、工具如何结算、哪些成果已经可用。** Temporal 负责下一步的执行、等待、取消、并行汇合、重试和版本路由。PG 保存业务问答、作品、来源、用途、预算、命令及效果回执。采用 Pi Agent Core 承载单个回合步骤，Pi AI 提供流式采样和对应的原生协议元数据。Mangekyō 可注入模型、重建上下文、限定工具执行与结算。[Pi SDK 决策](../adr/0010-pi-agent-sdk.md)

从 Codex 采用回合内更正、动态工具和压缩后恢复的验证用例。从 OpenCode 采用收件箱投递、已发布输出续接和子任务结果补送的验证用例。Pi Core 提供可插接的回合步骤。Mangekyō 的长期会话恢复、等待和后台教研由 Temporal 驱动。

## 2. 谁持有状态

| 所属 | 持有内容 | 调用关系 |
| --- | --- | --- |
| **领域模块** | 事实、命令和可接受的推导、可打开的块 | 人和 Agent 使用同一命令及读取入口。正式评估、掌握度、诊断和安排由所属槽位产出。 |
| **会话宿主** | 工作单及业务问答的定义、公开事件格式、工具和模型编排规则 | 由输入和前一步结算决定可进行的步骤。会话工具通过内核读取、发命令、请求槽位及受控计算。 |
| **Temporal** | 活跃执行代次、消息消费顺序、步骤位置、等待、计时、取消、子任务汇合、运行版本 | workflow 只传受控引用与必要控制状态。所有读写、网络、代码运行和资料投影在 Activity 里。 |
| **内核和存储** | 当前与历史版本、输入清单、对外可见的业务事件、许可及预算、稳定命令与效果回执 | PG 的状态可以证明发生过什么、哪些成果可见。恢复时凭 Temporal 提供的步骤身份取回回执。 |
| **模型适配器** | 传输中的单次流、模型身份、结构块、调用参数、结束原因及本次 usage | 执行宿主已准入的请求。取消、可选重试及发送次数受效果边界控制。引用和短期提供方元数据受当前用途与留存策略约束。 |

面向产品的接口以行为为准，下面是入参和返回值的最小形状。正式的聊天入口、题下同伴、课堂、备课与教研从同一入口触发会话；模式由工作单决定。

```ts
// 业务身份跨 Worker 重启和 Temporal Continue-As-New 保持。
submit(workOrder, firstInput, requestId): { sessionRef, turnRef }
send(sessionRef, input, { delivery: "steer" | "queue", turnRef?, requestId }): InputReceipt
stop(sessionRef, { turnRef?, requestId }): StopReceipt
observe(sessionRef, afterEventId?): Stream<VisibleEvent>

// 单次采样。授权后的请求由效果 Activity 下发。
streamModel(request, signal): Stream<ModelEvent>

type ToolDescriptor = {
  name: string
  declarationVersion: string
  schemaRef: string
  preconditions?: string
}
```

工作单记录目标、交付要求和验收条件、允许使用的数据和外部能力、父预算、可见交付位置以及触发来源。上下文由引用重建。子工作单声明各自交付、用途、预算份额和何时把结果交回。工作单属于会话业务定义，和执行位置分别存放。

### Pi 的接入边界

每个步骤的 Activity 通过 `runAgentLoop` 接纳新输入，或在已有用户输入、工具结果时通过 `runAgentLoopContinue` 续接。用 `prepareRequest` 和 `transformContext` 注入实际工具定义、获准的上下文及模型路由。自定义 `streamFn` 通过效果账本发起或重放这次采样，完整保存结束原因、正文和工具请求。工具经内核检查与结算，长计算返回工作引用，交给 Temporal 等待。`finishTurn` 在批次结算后结束这次 Pi 执行，Temporal 决定下一步骤。

若 Worker 在采样完成后、工具尚未全部结算时中断，从采样前的上下文恢复本步骤。向 Pi 重放已保存的采样，逐项读取同身份的工具回执，只有具备执行资格且未执行的工具才继续。下一步骤从已结算的工具结果续接。已到达终止的 assistant 消息直接交给宿主核对交付。新学生输入由会话的持久接纳入口进入。

## 3. 会话如何执行和恢复

### 接纳与中途更正

1. 学生提交消息、交互、补页或更正。入口通过命令在 PG 事务保存规范化输入和业务回执，并登记给 Temporal 的 outbox。同一请求 ID 同参返回原回执。回执能说明已接收或已排队。若指定回合已结束，给出当前回合及“作为下一条发送”的选项。
2. Relay 将输入引用送到对应 workflow，workflow 按会话内序号去重与排序，缺序号时按已提交的输入记录补齐。`steer` 进入指定活跃回合，`queue` 留到下一回合。两种投递各记消费进度，消费序号较后的 steer 时仍保留较早的 queue。默认对话连续收到多条更正时，在同一次采样前按接受顺序加入。
3. 当前工具在安全边界结算。只读工具的结果仍获准时和更正一起进入下一次模型请求。涉及未执行的写入与外发时，资格检查同时比较已接收、已交付模型的输入序号。较新的更正先让模型重新取舍；较早已生效的动作保留回执和可用的撤销或修订入口。
4. 关闭回合的 Activity 与接纳输入用同一事务锁。它收到 Temporal 已处理的序号，锁内发现尚未消费的已接纳 steer 就返回给 workflow；否则提交最终可见结果与关闭回执。随后到的输入可按新回合接纳，并明确告知学生。已接纳的 steer 要么进本回合，要么收到明确、可回看的转投结果。客户端断开 SSE 时保留会话运行。显式“停止”改变执行资格，并按工具能力传播取消信号。

### 采样、工具和交付

| 步骤 | 应持久化的结果和下一步 |
| --- | --- |
| **准备采样** | 当前任务、权限和访问代次，输入范围、路由、允许的工具 schema、原文引用及窗口版本。生成稳定采样键并按内核规则登记效果和预算。 |
| **一次模型采样** | 显式收集正文、结构块、完整工具调用和提供方专用块。公开 SSE 以产出项为单位，临时片段和确认内容有独立状态。完整 assistant 消息与效果结算保留关联。流中断与正常结束分别呈现。 |
| **执行工具** | 用已完成采样与调用序号分配稳定工具键。已完整结束的调用才可执行，参数错误按原调用送回模型，半段参数和断流的工具批次不执行。并行用于互不依赖的读、求解和计算。写同一对象或依赖前一个结果时有序执行，命令仍作版本核对。 |
| **继续或等待** | 工具结果带同一个调用 ID 回到历史。槽位计算、子工作或材料未齐时，Temporal 按完成通知、到期、暂停或输入恢复。登记等待时重新读取被等待工作的状态与代次，先完成的子工作也能直接返回，重复通知按引用去重。工具返回可用时刻、等待引用与其他可继续的路径。 |
| **验证交付** | 用可打开的事实版本、有效槽位、工具回执和已提交正文核对工作单。提议、等待、部分可用、已取消、失败、外部效果未知都可回看。模型自然语言描述可以解释过程。产品的“已保存”“可开练”“已重判”来自对应结果。 |

一个 assistant 项可以同时含正文和工具调用。后续采样保留两者及对应回执，公开可确认的正文不会被无正文的后一步覆盖。只有写入回执且学生仍等解释时显示部分可用，保留可回看的回执和从原会话继续的动作。若任务的明确交付只有写入，则可由经核对的回执完成。学生活动、评估和交互产物同样以服务端接受结果决定是否可用。

### 效果、权限和可回放事件

- 使用逻辑步骤键 `(session, turn, step, operation)`。工具动作还包含完成采样内的调用顺序和工具声明版本。步骤由 Temporal 决定，版本升级沿已有在途执行兼容策略。已完成效果复用。确知前一次未执行时可登记新尝试；支持同键幂等且已实测的路由按提供方契约复核。已发送且结果未知留在原预算账上，优先查询或使用已有提供方任务句柄。相同身份不同输入按内核契约拒绝。
- 命令写入与回执同事务。读取和可重放的结果一并记录见证。识别、判分、题库验证、摘要和索引沿输入清单传播过时。固定历史版本可回看，当前判断受跟随与截至引用的有效性约束。查过哪些对象、哪句话实际引用了哪个原文片段、哪些来源决定产物生效分别记录。
- 外发在最后一个宿主可控的发送边界核对当前代次、目的、数据用途、接收方和预算，结算和生效前再次核对。预留效果与实际准入之间的撤权应阻断发送。已经交给外部传输的请求按在途处理，尽力取消，保留可核对的状态。撤权后旧结果不能进入下一次请求或产生新生效结果。学生活动仅凭版本有效也不能获得新的外发许可。
- SSE 发可重新读取的业务事件和临时正文片段。确认后的公开文本、产物身份、输入状态和真实工具回执可由 `afterEventId` 继续读取。已显示但未完整确认的片段明确为中断状态。重新订阅时要重验用途。调试、监控、Temporal 历史与 PG 效果记录都按载荷寿命处理，原文、隐式推理和密钥不会作为公开事件。
- 主题、操作、身份、费用和授权都有实现见证。仅本轮、不留存临时、撤权和永久删除覆盖原文、摘要、索引、附件、推理块、请求响应、回执载荷、缓存、子任务和外部引用。用脱离长期备份的受控临时存储和可销毁密钥。删除只留不可复活的控制凭据，效果账本中已删除的身份仍不能变回未发送。

### 上下文、记忆和上下文溢出

按路由测量实际可用输入量，为系统指令、工具 schema、图片、近期输入、回复及推理保留空间。准备采样时按以下顺序构建：当前工作单和最新学生输入，当前未结算的完整调用与返回，当轮已确认的交付目标，近期获准的对话，其余用带版本的摘要、证据和产物引用按需加载。工具调用和结果成对保留，工具参数和长文以条目或范围切片。搜索结果只证明找到了候选。部分读取只证明打开了相应区间。

记录本次投影的输入范围、摘要版本、保留起点、工具视图及授权见证。窗口替换和当前不可压缩输入有明确边界，同一允许用途下从刷新或 Worker 重启得到同一视图。压缩后保留引用、反证、未决问题与本人更正。切换模型或端点时重新估算，并用当前接收方许可重建。原生签名、服务端历史句柄及缓存只在兼容且许可的路由内复用。无法可靠测量窗口时采用经实际流量核对的保守能力值，或缩小当前读取范围并告诉模型如何继续。

正常超窗前可以按当前用途压缩，收到提供方拒收时依据是否已传输、是否有可见或持久输出、是否可核对费用决定后续。能确认未执行的请求可用新的投影重试。带有效部分结果的步骤保留原内容与回执，并支持继续。未知费用走效果核对。长期记忆是可编辑的学习数据，携带来源、用途、范围、期限及“本人声明 / 系统推断”。可据此找对原文，教学判断需要相应的真实作答及当时的帮助记录。

## 4. Agent 的工具接口

### 从已核对的产品取做法

| 对照行为 | 设计落实 |
| --- | --- |
| Notion `notion-search → notion-fetch`。搜索结果给可直接打开的 ID 或 URL，告诉 Agent 哪些筛选未用上。拉取的页面有路径、编辑时间，长内容或关联资源有后续入口。 | `search_learning` 给可打开的版本引用、命中摘要和发生时间。可以用关键词、时间、关联对象或当前页面直接找。题库的用途、可发放性、未见解法等硬条件始终成立。无法执行的检索条件明确指出；可省略的排序偏好可以带提示降级。 |
| Notion `notion-update-page` 可改单项属性或局部正文。异步写入给任务句柄，完成后取回实际结果。 | 教材和题的局部修改优先用模型已看到的块或作答位定位，返回新版本或提议。需要计算的操作返回等待引用和唤醒条件，完成后直接可打开真实产物。 |
| Linear `list_issues` 支持关键词和团队、状态等结构化条件，`get_document` 接受 ID 或 slug，`save_document` 省略 ID 表示创建，更新只传变化字段或原子 patch。 | 工具按对象命名，让“保存教材页”和“保存题目”分别具有窄参数。欢迎已知的标题、链接、稳定引用和类型上下文，歧义时给候选。只改变化的字段，内核用基版本处理冲突。 |

核对依据：[Notion 查找与打开](https://developers.notion.com/guides/mcp/tools-search-reference) · [Notion 局部修改和异步回执](https://developers.notion.com/guides/mcp/tools-pages-reference) · [Linear MCP](https://linear.app/docs/mcp)。Linear 的入参来自本机工具 `list_issues`、`get_document`、`save_document` 的实际声明。

### 查找、打开、使用与扩展

最常用的读取入口可以直接用。模型拿到题目页、课堂、当前作答等当前对象时优先打开引用。知道标题但有歧义时可以利用候选直接选择。应用提供展示深链，工具提供可重新打开的具体版本。标识由产品返回，模型能用手头已有的引用，无需从界面文案中拼 ID。

| 入口 | 最少入参 | 返回和引导 |
| --- | --- | --- |
| `search_learning` | `query?`、`kind?`、`related?`、`since?`、`cursor?`。空查询列获准的近期条目。 | `items[{ref, kind, title, excerpt?, occurredAt?, matched?, state?}]` 和下一页游标。限制筛选范围再搜索或重排，结果带命中依据与作用域。游标绑定查询和读取视图，有效性变化时指明如何重新查。 |
| `open_learning` | `ref`（当前对象、ID、深链或返回的版本引用），必要时加 `part` 或游标。可批量打开少量相关对象。 | 对象类型、获准内容或结构化片段、`ref`、事件时间、来源、关联对象、页程和状态。版本引用打开原版，延续游标固定原版并重验用途。需要最新版本时可打开对象本身。 |
| `find_tools` | `query`，如“请求重判”“维护知识关系”“导出本轮验算文件”。 | 从已加载命令、槽位、受控能力选出少量最相关的 `ToolDescriptor`，下一模型步骤按描述符加载相应版本的短 schema。被授权且工具名已明确的常见操作由所在入口预置。 |
| `wait_for_work` | 一个或几个当前会话可用的工作引用，可要求到齐或先接收任一结果。 | 已完成即给可打开的结果。其余返回可继续的选项和唤醒条件，宿主登记 Temporal 等待。插件异步任务按协议预算和建议间隔查询，已有事件则订阅。 |

`open_learning` 可以把“我上次怎么解的”回答需要的内容作为一次结构化读取返回：原作及时间、当时题面与作答位、实际显示过的帮助、判分或未知状态、卷与材料的可导航引用。常见的其他读取包括“这个考点下我没看过解法的候选题”“该技能当前掌握度及支持和反证”“教材图谱的先修和关联题”。搜索给轻量预览，读取载荷按对象结构分段，证据引文可用 `{ref, part}` 深链。跨条目、大范围查询的时间水位进输入清单。

工具 schema、领域校验和界面命令共用同一声明。必要的说明、可导航关系、可检索字段和权限提示作为事实类型、命令或槽位的声明属性，遵守原有目录加载。一个领域操作定义一次。业务块使用已有读写入口。内核内建发现、读取、受控计算和等待，领域模块仍只有四种构件。构建验收覆盖承接表中的每类对象：记录主读入口、版本追溯、授权写入动作或触发该推导的命令、真实可用的界面入口。

发现回执存下描述符，下一步骤的工具视图按 `schemaRef` 加载同版定义，并固定执行方。恢复时用原调用结算或按已固定的声明版本解释，执行前再查现行权限。版本退役时由兼容策略解析原版，否则明确返回版本变更及重发现动作。给模型的名称与底层命令明确对应。外部 MCP 同名工具纳入独立命名空间，描述符使用联接身份和已发现 schema 的版本，工具清单变更时重新发现。

### 写入和持久成果

| Agent 意图 | 模型看到的调用形状 | 内核和返回 |
| --- | --- | --- |
| 写教材、记方法，或修改其中一段 | `save_page({title, content})`；`save_page({ref, patch:[{block, replace}]})` | 新建可保存草稿。传已读版本和变化字段补丁。更新学习者作品返回可比较、分项采纳的提议。已有块标识可直接使用。 |
| 创作题目或新题形 | `save_question({prompt, response?, evaluation?, interaction?, sources?})`，后续可传 `ref` 局部更改 | 支持仅给题面保存草稿。要可发题时检验版本绑定、作答结构、交互、评估方法和独立求解。状态返回草稿、待核对或可用，缺什么给对应下一操作。 |
| 改一处误录，复核一题 | `correct_transcription({ref, part, text})` 或 `request_review({attempt, reason, part?})` | 修订保留图上位置和本人更正，按授权身份入账。OCR 更正使相关推导重验。评估申诉有独立请求和评估槽位，保留原判和新判。 |
| 写学情观察、维护知识关系与长期记忆 | `record_observation({about, evidence, detail})`、`save_relation({from, to, relation, sources?})`、`save_memory({detail, sources, scope?})` | 区分学生声明、同伴观察和正式推导。发现原文没打开或仅见部分时给可打开的引用和需要的片段；未知、反证、用途与期限可表达。 |
| 组织学习或发起委派 | `prepare_activity({goal, ...})`、`request_assessment({attempt, criteria?})`、`delegate_work({goal, deliverables, refs?})` | 已开放的槽位依需求唯一登记。委派带父工作单、允许用途及可用预算，结果引用回到父会话；发题、发布安排和教师批注等各走各自已有命令。 |
| 查公开资料、写验算并复用结果 | `search_public({query})`、`run_calculation({code, inputs?})`、`edit_artifact({ref, patch})` | 对外检索把允许外发的查询连同来源回执入账。计算输入接受已列明的授权引用，返回可再打开的标准输出、产物、错误位置和下一操作。保留需长期复用的产物，走所属领域的采纳。 |

这些是模型侧接口形状，最终由相应声明生成工具。读取全部对象与发起领域操作是产品范围。对事实使用命令修订、采纳和提议；学情、判分、预测之类的推导可重新请求计算、提供更正依据、对当前评估发起复核。它们的生效由内核校验。学习者自己的提交、帮助实际曝光、锁定和授权均保留作者及真实发生时点。Agent 可录入获准的本人说明、教学习、提议变更，动作和作者有准确回执。

典型回执形如 `{status:"saved"|"proposed"|"pending", ref, href?, related?, next?}`。没有产生新版本时返回具体原因。提议给可打开的差异。当前版本冲突给已获准的当前引用和重读动作；若改的是同一个块，要求选择差异或由学习者采纳。已明确授权、可逆的内部操作可以直接完成；本人作品替换、用途扩大、锁定变更和永久删除走对应领域的本人确认。

“第 3 题照片上是 48，抄成了 18，按原规则再判一下”的调用可从当前作答直接开始。引用都可由上一个结果复制，以下用短值表示。

```text
open_learning({ref:"current_attempt", part:"第 3 题"})
  → 作答@2、手写证据@1 的第 3 题区域、发题@4、评分契约@3
correct_transcription({ref:"手写证据@1", part:"第 3 题答案", text:"48"})
  → saved 手写证据@2，相关评估过时，链接更正后的作答
request_assessment({attempt:"更正后的作答"})
  → pending 重判工作，沿发题时锁定的评分契约执行
wait_for_work({refs:["重判工作"]})
  → 判分@5，依据为手写证据@2，评分契约仍为@3
```

“把那道点选断句题加进周五练习”可直接查题或打开已知引用。若题目正等待评估规则核验，工具返回已完成的题面和对应等待引用。Agent 有足够的其他候选时可以先编卷。含这道题的草稿保留可编辑，正式发放时由卷面冻结命令核对目标题版本、规则、可操作块和未揭示的答案。结果显示可打开的短卷或具体待办。

### 少阻拦，多引导

- 让常见调用的最小参数就能工作。省略顺序、分页上限、记录时间和可从同一版本推得的字段，由宿主给语义明确的默认值；不给模型传适用不明的内部 ID 或自动生成的控制字段。标题与精确引用均可被解析。相同标题的选择有时间、上下文和版本。
- 缺字段、错类型、非法 JSON、歧义、旧版本和预算不足都是模型能继续处理的结果。用短错误码、实际出错字段、简短原因和可直接使用的修正动作。例如 `{code:"version_changed", field:"ref", message:"该段已更新", next:{tool:"open_learning", args:{ref:"<获准的当前引用>"}}}`。同一输出支持返回可用部分和后续位置。修正由 Agent 决定，额度和停滞状态由工作单约束。
- 工具暂未加载时给发现入口和值得找的操作。拿不到原文时给当前可用的替代或请本人补充的理由。未获批准的对象用无内容的不可用结果，报告当前访问情况，避免从“查不到”推断“已删除”。提供方不可用时优先给可用的已验证产物或确定性路径。
- 受控计算提供 Python、符号计算和按任务隔离的代码运行。支持读、按块改文件、跑验算、获取带版本产物和错误位置。中途计算可互相引用成果，持久产物经命令采纳。对模型开放的网络和 MCP 能力按授权接入，传输限定接收方与可外发输入。第三方返回、文档和代码作为资料读取；嵌套工具调用经过同一权限与效果检查。

## 5. 常驻教研

### 启动、找工作和等待

1. 学习者开启后台教研后，由配置命令和既有 outbox 启动或唤醒每位学习者稳定身份的 Temporal 协调 workflow。后端启动时对已开启配置校对一次可运行实例，通过同一幂等入口补启动，前台关闭和重启无需用户操作。预算未设时可算确定性提示和展示已有成果，付费余额为零。
2. 在开始、阶段结束、依赖变化、学生反馈和自定复查时点，协调 workflow 以当前用途读取轻量概览。来源包括未完成研究及可直接回看的旧作品、学情反证、评估更正、学校进度、锁定、已备活动、已拒绝意图和已有工作或产物。内部唤醒定时器可以由上一次会话按依据设置，空待办也能在获准预算内做一次发现。
3. 同伴在同一个会话能力上决定值得推进的机会，输出候选工作单，包含目标、原始依据引用、交付物、完成条件和预算请求。宿主执行确定性准入，检查允许用途、暂停代次、与已有工作和可用产物的重叠、实际剩余额度及用户拒绝。已有可用材料先返回链接。未满足条件时给可等待事件、到期时点或保持空闲的理由。
4. 工作可以并行安排资料查找、独立解题、备讲义、准备图及编卷。各分支共用父预算，由内核原子划拨，未知费用仍占用，交互有单独额度和执行队列。子任务完成后的结果和实际检验回到工作单，父会话重新检查取消代次、证据与产物资格后再发布。无模型时沿原规格提供当前可学内容。
5. 完成的会话保存发现、已有产物和下一项值得检验的条件。允许立即沿有新产物或新证据的线索续作。重复同一依据与意图、没有可用产物变化、缺待处理原文或额度不足时进入等待。按下一次可唤醒条件登记，缺条件时退避到允许的复查点或显式等待配置变化，避免无收益的采样循环。

同意暂停、撤权、配额用尽与用户拒绝有不同语义。暂停推进配置代次，并停止新的后台模型发送，取消在途分支并核对已发生效果。恢复时重读现行用途、已保存产物和预算，从可用工作继续。关闭界面不暂停。原工作只有在其交付物、有效依据及完成条件满足时才完成。已归档课、已发卷和学生锁定项通过原命令约束保护。

长期 workflow 按历史增长建议在安全等待点执行 Continue-As-New。先排空已接纳的消息处理、结算正在变更的控制状态，再携带稳定身份、必要游标和等待引用。新执行从 PG 重读仍未消费的已提交输入及最新配置；以稳定身份去重。分析、原文、大产物、费用详情和授权资料均留在业务存储。参照 [Temporal 消息处理](https://docs.temporal.io/develop/typescript/workflows/message-passing) 与 [Continue-As-New](https://docs.temporal.io/develop/typescript/workflows/continue-as-new)。

### 常驻教研的首项验收

让有额度的服务从空队列启动，只放获准的旧讲义和两份有区分力的旧作，关闭所有客户端。验收期间不给新消息、新材料或排好的课。实际看到同伴找出旧讲义，打开两份原作及当时的帮助，提出能看见差异且来源可打开的修订。在第一阶段结果已保存、下一阶段尚未开始时杀掉 Worker，重启后自行从该处接续。第一次打开页面能看见离开期间的成果、依据与时间。对照试验改变暂停开关、删除一份依据和压低预算，分别观察停止发送、丢弃不再有效的候选和已有材料兜底。
