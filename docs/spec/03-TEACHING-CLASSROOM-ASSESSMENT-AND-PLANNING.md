# 03｜学习型课堂、Generative UI、练习试卷、同一评估契约与动态「今天」

- 归属模块：`modules/activity`、`modules/plan`（协同 `modules/content`、`modules/learner`）
- 覆盖范围：PRD §2.3、§2.4、§2.6、§2.7、§2.9、D03（Generative UI）、D04、D05、D08、D09（F19–F33、F47–F57、F64、F70、F73）

## 1. 学习型课堂（`modules/activity`）

### 1.1 按次编排、随时调整、用后归档
- **定位**：每堂课围绕学习者此刻想弄懂或做成的一件事按次独立编排，由「讲解块 + 交互图/演示块 + 嵌入式题目/随堂检查 + 可选后续分支」组成活讲义。
- **多入口开课**：可从「今天」直接进入后台预备好的课堂，也可从正在做的错题、教材页、知识点或自由对话里随时请同伴开课。
- **动态调整与跳过**：
  - 上课过程中学习者随时可插话、卡壳或表示“这块我会了”；
  - AI **仅动态重编尚未呈现的后续步骤**（已发生的讲解、作答与帮助原样保留）；已掌握步骤可跳过，达到目标可提前结课。
- **完整归档与冻结**：
  - 课堂结束后归档冻结当时的讲义编排、题目版本、学生作答、交互状态与帮助曝光；
  - 后续题库或个人教材修订**绝不追改已归档课堂**；重新编排同主题课程生成新课堂实例，绝不覆盖旧课堂；
  - 学生可一键把课堂中有价值的图、例题与总结提炼进个人活教材（走 `content` 采纳/Diff 提议）。

### 1.2 全套具名教学方法与角色活动（必须真实可执行，非文案）
1. **分阶提示（Graduated Hints）**：复用预备提示并从上一阶继续，支持 L1→L2→L3→揭晓完整解答（明确动作），**只有实际展示给学生才写入 `help_exposure`**，不重复收费生成已完成帮助。
2. **例题渐隐（Worked Example → Faded → Independent）**：完整示范 → 关键步留空补全 → 独立做新题，三步有独立观察记录。
3. **自我解释（Self-Explanation）**：先让学生用自己的话解释关键一步或做出预测，再用图/操作或反例检验。
4. **无标签方法辨析与交错练习**：**严禁在题目标题或引导语中提前泄露应选方法**（例如把题标成“用能量守恒解”），强制学生自主辨析方法。
5. **先试再讲（Productive Failure / Try-First）**：先给最小可试探任务收集真实尝试，再基于学生自己的卡点精准讲解。
6. **聊天内检查题正式化（F30）**：伴学对话中出的每一道检查题都必须创建正式 `activity` 实例，学生回答成为正式 `submission` 进入学习史与对账链路，**严禁只留在无法检索对账的纯聊天记录里**。
7. **教同伴（Teach-the-Companion，F70）**：明确标注的角色练习——学生负责讲解，同伴扮演学习者复述、提精准追问与给反例；**之后必须安排独立迁移任务检验理解**（角色扮演过程不冒充系统真有该误解，讲顺了也不直接判掌握）。
8. **共同创造学法模板（F64）**：学习者与同伴可把已有活动与块组合成有名称、有版本、可编辑的方法模板（如“先预测 → 构反例 → 独立检查”），保存目标、步骤与观察要求，替换模板不改历史；不做万能代码编辑器。

## 2. Generative UI 与版本化交互块（跨题目 / 教材 / 课堂 / 同伴统一）

- **统一交互块契约**：Agent 依据当前教学目标选择、参数化生成并组合产品支持的交互块（可调参数坐标系/函数图、运动/物理过程滑块模拟、双解法对比视图、先预测再揭示检查块、字间断句器、多轨节奏鼓机、几何画板等）。
- **计算产物驱动**：支持直接绑定 Python 沙箱生成的精确数据/SVG/仿真结果（`@calc_*` 句柄），杜绝大模型凭空画错函数曲线或比例失真的示意图。
- **实时反馈与状态回传**：
  - 探索态下支持反复拖动、试听、撤销并即时看到与条件一致的视觉反馈；
  - 学生点击“问同伴”或“提交检查”时，将当前交互状态 JSON + 块版本 + 绑定对象一并回传给同伴或评估引擎，同伴据此精准回应刚刚的操作；
  - 严格区分「探索操作」「草稿保存」「正式提交」「观看帮助」。
- **防剧透与无障碍**：
  - 独立检查块在学生提交预测/答案前，**客户端收到的载荷不得包含答案或解答图**；
  - 任一交互块必须提供等价的键盘/触屏/表单操作路径；块渲染失败时保留完整可读题面、已写草稿与明确恢复入口。

## 3. 练习型试卷与智能组卷（`modules/activity` + `modules/content`）

### 3.1 一句话组卷与多目标筛选
- 学生可从学校原卷、单题直练、知识点、个人教材或同伴对话发起组卷，一句自然语言即可指定范围、目的与时长（如“20 分钟读图练习，重点练斜线段并检验陌生问法”）。
- **智能组卷引擎**：
  1. 先用 IQDB 硬过滤（用途、可发放、无答案冲突）；
  2. 按目的区分曝光约束：**巩固**可有意重做原题再换条件；**迁移检验**必须选用未做过且未见过同族完整解答的独立题（找不到时诚实标出“仅做巩固、迁移待检”）；
  3. 综合覆盖率、关键步骤、冗余度与**真实时间预算（含读题 + 切换 + 复盘时间；缺用时证据时给暂估区间并留余量，时间不够就减题并说明未覆盖部分）**；
  4. 开卷前透明展示：本次目的、预计时长、覆盖知识点、来源与缺口，允许学生调整范围再开卷。

### 3.2 冻结作答与整卷复盘
- **开卷即冻结**：题面、顺序、共享材料、作答位与评估契约全部锁定；支持跳题、回看、暂停、自动草稿暂存、跨设备续做、明确提交已做部分（未做题保持未交而非误判错）。
- **过程信号自动采集**（无侵扰）：
  - 前台有效作答用时（切后台/锁屏不计解题时间，缺失记 `unknown`）；
  - 关键草稿修订、跳过/放弃、求助与提示阶次、学生可选信心评分与自评；
  - 若前题获得的提示实际上教到了后题需要独立完成的方法，复盘与学情须显式标明跨题帮助污染。
- **整卷复盘出口**：逐题清晰分开「完成状态 / 答案结果 / 关键步骤过程证据 / 受助范围」，每道错题一步直达：更正识别、提出申诉、打开对应教材页、安排一堂微课、或开原卷重做/新变式。

## 4. 同一评估契约（Unified Assessment Contract）

无论单题、整卷、课堂检查、画图构造、作文还是代码项目，全部服从同一评估契约，回答同一组问题：**发的哪版任务、实际交了什么、冻结规则是什么、哪一步有证据、哪些仍未知、下一步能做什么。**

1. **全形态真实评估**：
   - **选择与数值**：支持数学等价形式、单位换算与合理精度；
   - **分步解答**：按关键步骤分开评判结果分与过程质量；前一步算错但后续按所得中间值逻辑正确推进时，按该卷冻结规则保留过程证据；
   - **画图 / 交互构造**（如几何画图、音乐鼓机）：校验是否满足全部约束，天然接受多种不同满分作品；
   - **作文与开放题**：按冻结评分维度给逐项质性反馈，引用学生原句片段；只在规则明确定义分值处计分，无法客观判定的风格项如实标 `unknown` 且不计入掌握度；
   - **代码项目（PRD §2.7 / 单元 27）**：必须由**受控隔离代码沙箱真实执行**学习者提交的代码并运行测试用例（绝不用 Python 记忆 worker 冒充），再结合 LLM 读代码给出过程与边界反馈。
2. **明确分离的评估状态**：严格区分 `unsubmitted（未交）`、`clarification_needed（识别待确认）`、`pending（待判）`、`method_conflict（独立解答冲突）`、`ungradable（无法评估）`、`incorrect（有依据错误）`、`partial（部分正确）`、`correct（正确）`。部分无法判定时，可确定的部分仍立即反馈。
3. **三权分立：识别更正 ≠ 本人自评 ≠ 正式申诉（D09 / 单元 39）**：
   - **识别更正**：改的是源提交/抽取事实，触发受影响判分、掌握度与未开始安排自动重算；
   - **本人自评**：独立事实保存，绝不覆盖正式评估或伪造独立掌握；
   - **正式申诉**：带理由提交复核请求 → 触发独立新评估（可使用 Python 验算或高档模型核对原卷规则），**保留原评估与复核状态，允许维持原判或部分改判**；仅重评完成后才更新依赖它的当前判断。

## 5. 目标生命周期与动态「今天」（`modules/plan`）

### 5.1 目标与约束事实（粘性、由学习者做主）
- **目标状态机**：`active（进行中）` / `paused（暂停）` / `completed（完成）` / `exited（退出）`；系统可根据证据提议“可能已达成/长期停滞”，**必须由本人确认变更**，退出不标为失败；目标暂停/完成/退出后立即停止按旧目标自动备课。
- **丰富现实约束**：支持考试日期与范围/题型权重、学校课程进度、超前预习、每日/每周可用时间段、例外日期（如“周六不学”）、以及显式锁定的活动。
- **有期限当下声明**：自述“今天累/考前慌/今晚只有 15 分钟”等必带范围与绝对失效时间（默认本次时段结束或当日 23:59 先到者），跨日不延续，绝不固化成永久标签。
- **保护与冲突透明**：
  - 显式锁定、正在进行、已完成活动受到硬保护；跨零点不重置正在进行的活动或清空草稿，**绝不制造惩罚性逾期欠账墙**；
  - 约束冲突时明确指出哪两项无法同时满足并给可选方案，绝不暗中挪动锁定项。

### 5.2 动态「今天」编排与机会成本权衡
- **真实约束 + 真实内容决策**：规划推导器先结合目标、DDL、时间预算、锁定项、**已知会发生的学校作业**、自研遗忘紧迫度与信息量价值筛出候选，再由 Agent 阅读真实题目/材料内容做最终编排（如果模型服务全挂，由纯确定性规划推导器无缝兜底，「今天」永远不空）。
- **每项推荐必须说清 4 件事**：
  1. 准备好的直接可打开实体（课堂 / 短卷 / 复习 / 摸底，**未备齐材料绝不标为可用**）；
  2. **为什么此刻做**（附直达证据，例如“昨晚两道错题都漏了停车段”或“30 小时后保持率将跌破阈值”）；
  3. **预计时长与依据**；
  4. **推迟会带来什么影响**，且**休息/推迟/换选始终平等可选**。
- **带标定的考试总分区间预测（F70 纳入部分）**：仅当考试范围/权重、适用评估证据与方法标定三者齐全时，才输出事前冻结的总分区间 + 标定误差；缺任一项必须诚实返回 `unknown`，**严禁无依据的精确提分承诺或按分钟收益排行**。
- **长假回归与空库首次使用**：
  - 长假（如 3 周未打开）回归：绝不堆 200 条逾期复习，先给概览（哪些大概还在、哪些大概淡了），再按信息量安排少量摸底题，依摸底结果重排；
  - 空库且无模型（D08）：不强迫问卷、不强迫建知识树、不强迫填 API Key；内置明确标注来源版本的免费阅读/推理与确定性检查内容包，让学习者零配置也能立即打开、作答、看确定性反馈并创建自主学习记录。

## 6. 本域禁止糊弄清单与硬验收矩阵

### 禁止糊弄清单
- ❌ 禁止把「今天」做成静态待办列表 + 固定示例入口，必须由 `modules/plan` 结合目标、时间、学校作业、遗忘紧迫度与锁定项动态编排并解释原因。
- ❌ 禁止在无标签方法辨析题的标题里写出解法名称。
- ❌ 禁止聊天中出的检查题只存成纯聊天文本而不建正式活动/提交。
- ❌ 禁止用记忆 worker 或 LLM 假装“脑内运行代码”代替真实隔离代码执行器评估编程作业。
- ❌ 禁止把识别更正、自评、申诉混成同一条记录或直接覆盖旧判分。

### 硬验收矩阵
1. **完整学习型课堂闭环**：用新条件生成带可调滑块图与先预测后揭示检查块的课堂 → 学生操作后同伴引用本次状态动态调整后续步骤 → 跳过已会步 → 归档后修改题库/教材，重开归档课堂仍完整还原当时版本与交互状态。
2. **20 分钟智能组卷动态变化**：保持候选题库不变，分别改变（a）旧作受助状态、（b）同族解答曝光、（c）可用时间（20 分钟 vs 10 分钟），验证组卷结果、剔除理由与覆盖说明均合理变化，且答案冲突题绝不入卷。
3. **同一评估契约与三权分立**：对同一张试卷分别验证（a）分步过程分、（b）两种不同满分画图/构造解、（c）真实 Python 递归代码项目运行测试与主观风格 `unknown`、（d）更正识别 / 本人自评 / 提出申诉三条独立路径。
4. **约束动态重排 + 长假回归 + 空库无模型**：设置目标 + 锁定项 + 周四学校作业 → 取消周四作业后「今天」重算未开始建议且不动锁定项；模拟 3 周空白返回先出信息量摸底无欠账墙；清空数据库并关闭全部模型仍能完成内置确定性活动。
