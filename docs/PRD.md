# Mangekyo PRD

2026-11-17｜现行。Owner 已采用技术复审主线，并授权代理完成全部待定范围裁决；具体决定见 §3.1。推翻条件见 §11。范围决定不表示实现或验收完成。

Mangekyō 从一位学生的日常学习出发设计。查阅旧 the-learning-project 的最终实现，可以发现过去一位学生能做哪些事、哪些能力今天仍值得保留。学生会从哪里开始、同伴如何介入、背后需要什么结构，由本文的学习场景决定。学生遇到的新需求也可以独立进入产品范围。新仓库独立实现这些能力。

**证据边界。** 初稿依据旧项目的记忆、愿景与设计文档，以及 `docs/prior-design/` 的三份早先设计。2026-11-18 补入了[旧主线源码、当时的 TEST 回执与新版学生工作区验证](evidence/student-workspace/README.md)。文中关于延迟、成本和并行开发效率的说法是设计目标，尚未测量。

## 1. 产品

一个长期陪伴一位学习者的私人教研团。它的全部工作可以用一句话说完：**接住学习者的真实经历，形成可以被质疑的理解，在学习者开口之前把帮助备好，并用之后的表现检验自己帮得对不对。**

这句话拆成七件事，每件都必须成立，拆掉任何一件产品就不成立：

| | 学习者的感受 | 拆掉会怎样 |
|---|---|---|
| 记录 | 我交进来的一切都接得上，识别错了能改 | 每周都要重新解释自己 |
| 画像 | 它知道我会什么、不会什么、哪里还不知道 | 个性化只剩换皮 |
| 教研 | 我不在的时候它在备课 | 只是一个等我输入的聊天框 |
| 语境 | 任何学科、任何学法都能用 | 加一门课要改代码 |
| 供给 | 需要时总有好题、好笔记、好讲解 | 安排得再准也没东西可学 |
| 分寸 | 帮助恰到好处，不说教，不替我做 | 越难的时候越不想打开 |
| 算数 | 它的判断经得起检验，错了会认 | 所有「你会了」都是空话 |

学习者面对的只有四个地方，以及一个随处可用的动作：

- **今天**：已经备好的东西，每项附一句为什么。
- **同伴**：始终在场的对话者，能讲、能画、能出题、能改安排。
- **材料**：题、笔记、知识点、教材。人和 AI 用的是同一套工具。
- **我**：状态、目标、它对我的判断准不准、我的数据怎么用。
- **交入**：拍照、文件、一句话，在任何地方都能做，没有单独的入口和表单。

## 2. 场景

每个场景分两段：学习者看到的，和系统在背后做的。背后那段使用 §4 的术语，规范定义在 `GLOSSARY.md`。场景里的数字是设计目标。

### 2.1 晚上十点，拍一张物理卷子

**看到的。** 在手机上连拍四页，点完成，两秒内显示「收到 4 页」。不选学科，不选题型，不填任何东西。可以直接锁屏。如果还看着，半分钟后九道题带着自己的作答出现，六对三错，每道错题一句原因。其中一条写着：「第 7 题的答案我看不清，是 0.5 还是 0.8？」

**背后。** 「交入材料」是一条命令，写入四条原件事实，回执立即返回，之后的一切都不阻塞它。内核发现这些原件上的抽取槽位是空的，四页并行抽取。抽取的候选里有题目、手写作答和红笔痕迹。题目被采纳为内容事实，手写被采纳为提交事实，两者都带着来源，指回那次抽取。红笔按学习者的偏好处理（他的红笔是事后订正），单独记录，不算作答。

接着每道题有三个槽位被填上：解答（系统自己解，卷子上没有标准答案也不需要）、判分（结果分和过程质量分开）、错因。解答由两个独立方法各做一遍，不一致才启用第三个。第 7 题的手写识别结果是「未知」，这是合法的值，判分槽位因此等待，系统只问一次。

判分生效后，相关知识点的掌握度槽位过时并重算。重算用的是记忆模型，不是语言模型。明天的安排槽位也过时了，但此刻没人要看，先不算。

### 2.2 「第 3 题我选的是 B，不是 D」

**看到的。** 对同伴说一句，或直接在题上改。几秒内这道题从错变对，掌握度的一项变了，明天的安排换掉一项，旁边注明「因为你更正了第 3 题」。

**背后。** 更正是一条命令，给那条提交事实写入新修订，作者是学习者。旧修订保留。第 3 题的判分、依赖它的掌握度、依赖掌握度的安排，输入清单里都引用了旧修订，立刻成为过时。没有任何模块为此写传播代码。

恰好此刻有一个后台规划刚按旧掌握度算完，提交候选。内核在生效前核对输入清单，发现依据已过时，拒绝。它不依赖「失效通知」是否送达。

学习者改过的东西是粘的：以后即使用更好的模型重新抽取这张卷子，第 3 题的作答也不会被改回去，系统至多提出一个提议。

### 2.3 早上七点，公交车上打开「今天」

**看到的。** 三件事，共二十五分钟（他说过早上只有这么多时间）。一份讲楞次定律方向判断的短笔记，因为昨晚两道错题都错在这里；一道变式题；一道三周前做对、现在该再看的题。最下面一行：「动量守恒我只见过你做一次，现在还不知道。」

**背后。** 昨晚他锁屏后，「明天的安排」过时且学习者不在场，这触发了一次教研会话。会话带着工作单：目标是备好明天，交付物是一份生效的安排和安排里用到的全部材料，完成条件是这些东西都存在。

会话读掌握度视图、目标和时间约束，然后请求推导：一份笔记；五道候选变式题，每道由三个独立解答并行验证，解答一致的才被采纳进材料；最后是安排本身。安排的推导器先用记忆模型的预测和错误统计筛出候选，再由 agent 看着真实题目内容做最后选择。交付物齐了，会话结束，花费记在每个推导上。

如果那晚模型服务全挂了，安排槽位还有一个纯确定性的推导器兜底。「今天」永远不是空的。

如果昨晚没有任何新事实，什么都不会运行。后台由需求驱动，不由时钟驱动。

### 2.4 在平板上做题，卡住了

**看到的。** 做到一半卡住，问同伴。得到的是针对他当前这一步的一句提示，不是答案，一秒内开始出字。同伴顺手画了一张受力图，笔画一笔一笔出来。他做完提交，立刻知道对了。

**背后。** 同伴是一个会话。它能读的东西和学习者能看的一样多：这道题、他的草稿、他的掌握度，以及这道题的解答。解答在题目入库时就已推导好，所以提示不需要现场解题，首字才能快。

提示一旦显示，就写入一条「帮助曝光」事实。之后的提交照常判分，但掌握度的推导器把带提示的作答只当作弱证据。这条规则写在学习者模型的推导器里，界面和同伴都不需要知道它。

同伴前后没有分类器，也没有另一个模型审查它的回答。它直接回答。

### 2.5 「我电磁感应到底行不行」

**看到的。** 一段直白的话：感应电流大小的计算是稳的，三周内五次独立做对；方向判断不稳，四次错两次，两次是同一个原因；自感现象从没见过，不知道。点任何一句，展开的是支撑它的那几次真实作答。末尾：「做三道题我就能知道自感这块，要现在做吗？」

**背后。** 这段话读的是掌握度推导。每个掌握度的值都带不确定性，「不知道」是值的一种。点开看到的证据，就是那个推导的输入清单，所以解释不需要另写一套逻辑。

「三道题」是规划推导器按信息量挑的：选哪几道最能缩小不确定性，这是统计计算。

同时系统记下一条预测：「下次方向判断类题目，正确率约六成。」之后的真实作答会和它对账。对账结果也是推导，显示在「我」里：过去一个月，它说六成把握的地方，实际对了多少。

### 2.6 「28 号期中，物理考到第三章，每天最多一小时，周六不学」

**看到的。** 一份两周的安排。他把周日的整卷练习锁住。第五天老师改了范围，他说了一句，安排重排，锁住的那项没动，并说明去掉了什么、为什么。考完他拍了卷子，看到的是哪些失分在预料之中、哪些不在。

**背后。** 目标、时间约束、锁定项都是学习者写下的事实，不是推导，系统不会覆盖。安排是推导：约束求解负责排进时间，agent 负责判断内容。它对目标是跟随引用，所以范围一改立即过时并重排；它对教材抽取结果是固定引用，那部分直接复用，不重算。

考后的卷子走 §2.1 的同一条路。区别是此前的预测现在有了大量对账数据，校准推导更新，下一次的把握程度会据此调整。

### 2.7 自学一门没人教的东西

**看到的。** 他想提前学 Python 递归，把教材那一章丢进来。得到一份可以读的笔记，读到关键处有小检查；之后是一个小项目：写一个遍历目录的函数。提交的是代码，没有分数，反馈是「终止条件写对了；空目录的情况没处理；风格这部分我没法客观判断」。

**背后。** 系统此前没有「信息技术」这门学科。一次会话和他一起起草了学科语境：这门课学什么、怎么算会、怎么判。语境是内容事实，没有为它写代码。

项目是一种学习活动，提交是代码。评估的推导器是组合的：一个执行器真的运行代码，一个语言模型读代码。无法客观判断的部分以「未知」如实表达，不折算成分数，也不进入掌握度。

### 2.8 地铁里没有信号

**看到的。** 手机离线。今天的三件事都还在，做了两道题，又拍了一页笔记。出站后什么都不用做，平板上看到的和手机上一样，两道题已判完。

**背后。** 客户端保存着上次拿到的视图，以及一个待发送的命令队列。每条命令在创建时就有标识，联网后重放，服务端凭标识去重，重发多少次都只生效一次。如果他在电脑上也做过同一道题，那是两次真实的作答，两条都记录。

客户端从不产生判断。离线时没有判分，只有「已保存，待判」。所以旧设备不可能用旧判断覆盖新判断。

### 2.9 三周没打开，回来了

**看到的。** 没有两百条逾期复习。只有一句大概的话：这三周里哪些东西大概还在，哪些大概淡了，然后是五道题的重新摸底，之后才是新的安排。

**背后。** 这三周什么都没运行，也没有花钱：没有新事实，学习者不在场，没有槽位需要重算。掌握度保存的是记忆模型的状态而不是一个数字，「现在还记得多少」在读取时按当前时间算出来，所以不需要每天刷新。

回来这个事实本身让安排过时。规划推导器看到的输入里有一段长空白，按信息量先安排摸底。

### 2.10 我想换一个记忆模型

**看到的（维护者）。** 读到一篇新论文。让一个便宜模型用 Python 写一个新的掌握度推导器，配上几组输入样例。跑一遍全部历史，得到一张对比表：在过去所有可对账的预测上，新旧方法各自的准确程度。新的更好，切换。发现不对，切回去。

**背后。** 新推导器和旧的落在同一类槽位上。全量重放产生的是不生效的候选，按槽位并行，在工作站或租来的机器上跑都一样，因为推导器只通过输入清单拿数据。对比用的就是 §2.5 的对账机制。切换是一处配置。旧方法产出的推导都还在，可读可回溯。

没有其他模块、界面或同伴的代码因此改变。

### 2.11 八个便宜模型同时开工

**看到的（维护者）。** 同时派出八个任务：一个 PDF 抽取器，一个作文评估方法，一个时间线块，一条「合并知识点」命令，一个新题型的判分方法，等等。各自在各自的文件里完成，各自带着输入样例跑通，合并时没有冲突。审查每个任务只需要看一件事：它的输出对不对。

**背后。** 见 §8。

## 3. 从场景得出的产品承诺

以下每条都能被检验，也都在某个场景里出现过。

1. **交入不丢、不问、不等。** 回执先于一切处理；不要求学习者分类。选择持久保存的原件保留到本人明确永久删除；不留存临时按本人预先选择的结束/到期策略销毁，普通处理失败或重算不能擅自删原件。
2. **更正真的传播。** 改一处，所有受影响的判断和安排跟着改；改之前的历史不被重写。
3. **学习者写的东西是粘的。** 目标、锁定、更正、手工编辑，系统的任何重算都不会覆盖，至多提议。
4. **「不知道」是合法的值。** 看不清、没见过、判不了，都如实说，不猜，不伪造分数。
5. **每个判断都能点开看依据。**
6. **帮助在开口前备好。** 回来就能用，不需要先管理后台。
7. **没有模型时仍然可用。** 「今天」不会是空的，已有的判断仍可读。
8. **系统给自己打分。** 预测与真实结果对账，对账结果给学习者看。
9. **只有独立作答才是强证据。** 看过讲解、用过提示的作答另算。
10. **任何学科、任何活动形态，不改代码。**
11. **换设备接着做，短暂离线不丢。**
12. **不在场、无新事实时，不运行，不花钱。**
13. **数据用途由学习者定。** 「只保存」的材料不被任何推导器读取。

## 4. 模型

场景背后反复出现的只有三种数据和三类行动者。

### 4.1 三种数据

**事实**是发生过的事和被交进来的东西。普通业务操作只能追加，或由新修订取代旧修订，旧修订保留。每条事实有作者（学习者、同伴，或「采纳自某个推导」），有用途范围。本人明确永久删除及预先授权的不留存临时销毁是不可逆存储生命周期例外，优先于历史留存；它不增加领域数据种类，详见产品规格 D06 与 ADR-0008。

**推导**是算出来的一切：抽取、解答、判分、错因、掌握度、安排、笔记草稿、对账，以及界面读的每一个视图。每个推导落在一个**槽位**上，带着**输入清单**：实际读过哪些事实修订和推导版本，用的哪个方法版本。普通操作中推导不可修改，只能被新推导取代；永久删除可以销毁其载荷，读取只能显示“依据已删除”，不能借历史接口恢复正文。

**命令**是意图。它是写入事实的唯一途径，带稳定标识，重复提交得到同一回执。

### 4.2 六条规则

全部由内核执行，模块和推导器不实现其中任何一条。

1. **生效要核对输入。** 一个槽位同一时刻至多一个生效的推导。候选要生效，内核在一个事务里核对输入清单的每一项仍然有效，再执行该槽位的接受规则。
2. **过时是算出来的。** 事实有了新修订，引用旧修订的推导自动过时，传递地。过时的推导可读、可展示，不能支撑新的生效结果。何时重算是每类槽位的策略：立即、有人读时、攒批。
3. **三种引用。** 固定引用锁定一个版本，长期有效（已发出的题面）。跟随引用要求对象仍是当前版本（安排所依据的目标）。截至引用指向一个范围在某时刻的内容（「到昨晚为止这个知识点的全部判分」），范围内有更正即过时，范围外有新增只影响新鲜度。
4. **采纳把推导变成事实。** 需要独立身份和后续人生的东西（一道题、一条笔记、一次从手写识别出的作答）由命令采纳为事实，带着来源。来源过时后，新的推导可以提出新修订；如果学习者改过这条事实，只能成为提议。
5. **用途约束读取。** 推导器读不到用途范围之外的事实。撤销用途等同于更正：依赖它的推导过时。
6. **破坏性命令标在定义上。** AI 发出时自动成为提议，等学习者确认。普通领域命令可撤销，撤销本身是命令；永久删除必须明确确认且不可撤销，不假称外部效果也能回退。

这套模型和增量构建系统同构：事实是源文件，推导是产物，输入清单是依赖记录，过时就是需要重建，产物可以在任何机器上构建。不同之处是许多推导器昂贵且不可重放，所以推导一经产出就保存，重算受预算约束，付费调用有稳定的效果标识以便核对是否已经发生。

### 4.3 三类行动者

**学习者**发命令，读视图。

**推导器**是「已固定的输入 → 候选」的方法。里面可以是语言模型、统计模型、求解器、代码执行，或它们的组合。同一类槽位可以有多个推导器，哪个激活是配置；关键槽位另配一个确定性推导器兜底。推导器没有环境权限：读取经过内核并被记入清单，输出只能是候选。

**会话**是带工作单的多轮工作，可中断恢复。同伴是一个会话，夜里的教研也是会话。会话能读视图、发命令、请求槽位及获准工具/计算。业务问答与证据保存在受用途与删除规则约束的存储；执行进度、等待与恢复由 Temporal 唯一负责，不再另设会话执行游标。

## 5. 结构

```
surfaces/     界面。发命令、读视图、渲染块，没有业务判断
modules/*     领域模块。定义事实类型、命令、槽位与推导器、块
kernel/       事实库、推导库、生效协议、命令入口、调度、会话宿主、用途与预算、运行与花费记录
executors/    推导器的运行环境：进程内，进程外
```

依赖只向下。模块之间只能引用对方公开的类型，不能引用实现。模块拿不到数据库连接、模型 SDK、网络和环境变量。

**模块里只有四种东西可写：** 事实类型、命令、推导器（含槽位类型和可选的接受规则）、块。没有路由、仓储、服务层、迁移文件和登记表。HTTP 入口、同伴可用的工具、命令行入口，都由内核从命令和槽位的定义生成，所以一条命令定义一次，人和 AI 都能用。模块不建表。

**模块按拥有的事实划分：**

| 模块 | 拥有的事实 | 典型推导 |
|---|---|---|
| capture | 原件及其修订 | 抽取、来源定位 |
| content | 题、材料、笔记、知识点、学科语境 | 解答、关联、检索索引 |
| activity | 学习活动、提交、帮助曝光 | 判分、过程质量、错因 |
| learner | 学习者的声明与偏好 | 掌握度、预测、对账 |
| plan | 目标、时间约束、锁定项 | 安排、备课需求 |
| companion | 对话、人格、记忆条目 | 上下文摘要 |

学科不是模块，是 content 里的数据。

## 6. 智能怎么组织

- **教研团是会话加工作单，不是子系统。** 一种后台行为是一份工作单定义加一段提示词。个性化来自上下文够丰富、agent 能读到，不为它建机制。
- **统计信号是推导，喂给 agent。** 连续错误、错误率、预测的记忆强度都作为输入摆在 agent 面前，不替它做最后决定。agent 决定时看的是真实内容，不是分桶后的编号。
- **agent 前后不加 AI 闸门。** 生效协议做的是机械核对。
- **验证靠独立重做，不靠评审。** 一道生成的题是否可用，看几个独立解答是否一致。
- **算数是内建的。** 凡是对未来的判断都留下预测，凡是预测都会被对账。换方法的依据是对账结果，不是印象。
- **模型按任务档位选择。** 推导器声明自己需要的档位，具体模型是一处配置。
- **人格属于同伴，全局一致，可定制。**

## 7. 技术决定

| 议题 | 决定 | 理由 |
|---|---|---|
| 控制面语言 | TypeScript（内核、模块、界面） | 命令/槽位/工具与界面共享契约；编译边界防意外耦合，不当作运行时沙箱 |
| 推导器语言 | TypeScript 或 Python，经同一协议 | 记忆模型、统计、求解器的生态在 Python。进程外执行器从一开始就存在，协议才是真的 |
| 存储 | PostgreSQL 领域事实/推导/回执/效果；原件和大产物在 S3 兼容存储 | 命令与 outbox 同事务；可靠交接到 Temporal。工作流历史不是领域事实库，所有载荷服从用途与删除 |
| 后台执行 | Temporal 唯一耐久执行层；内核按过时与需求决定做什么 | 执行进度、重试、等待、并行和版本路由交给平台；不叠 pg-boss 或自制会话恢复 |
| Agent 循环 | Vercel AI SDK 与官方 Temporal 集成；Python 能力按需用 Pydantic AI | 宿主封装依赖；工具统一经领域命令与受控效果，不能叠第二个恢复引擎 |
| 界面 | React，采用 Material 3 Expressive 的响应式 Web；手机、平板、电脑共用，一个设置面板管理配置并允许自定义 LLM 提供方 | 离线能力限于：已取回的视图可读，命令排队待发 |
| 部署 | 接口、TS/Python Worker、Temporal Service、数据库及对象存储；可从私有单机运行 | 交互与重计算隔离；按实际资源需求扩展，不按用户数推断计算规模 |
| 身份 | 单学习者；学习者作用域从第一天起是内核每次读写的参数 | 将来多学习者不改模块 |
| 仓库 | 单仓库多包，pnpm workspace；Python 推导器用 uv | |

上述主线已由 owner 采用，详见 ADR-0007 与技术复审。版本兼容、恢复和效果账本仍需真实验证。模块代码不直接依赖执行框架或 provider SDK，也不为隐藏名字重造通用工作流解释器。

**不在起点的设施及其触发条件：**

| 设施 | 触发条件 |
|---|---|
| 分布式计算框架、GPU 池 | 具体计算需要多节点、共享数据或加速资源；候选 Ray，按代表性负载验证 |
| 设备侧同步引擎 | 完整离线工作集/本地查询使简单缓存成长为自制同步系统时优先 PowerSync；原生客户端仍不做 |
| 受限代码执行环境 | 运行学习者交出的程序或任何不可信计算前必须具备，不等待第三方插件出现 |

加入其中任何一项都应当是新增一个执行环境或适配器。如果届时需要改模块代码，说明 §4 的模型有缺陷，按 §11 处理。

## 8. 开发方式

**工作单元**是一个推导器、一条命令、一个块或一个事实类型。系统增长的主体是推导器，而它是「固定输入 → 候选」的函数：有输入样例就能在没有数据库、队列和网络的情况下运行和检验。这是便宜模型能可靠并行的主要依据。

**结构上的保证**

- 一个任务要读的：所在模块、相关类型、内核上下文的类型。
- 没有共享热点：无中心登记表，无入库的生成文件，无台账。
- 写错当场失败：越界导入不通过编译；推导器拿不到未声明的输入；命令不标注是否破坏性不通过类型检查。
- 新单元由生成器产出可编译的骨架和样例位置。

**两级所有权。** 内核、事实类型、槽位类型是契约层，由强模型设计，变更少，单独提交。推导器、命令、块的实现是填充层，便宜模型并行完成，一轮审查，只看行为。界面的视觉设计由强模型做，与填充层通过块和槽位类型相接，互不阻塞。

**硬性上限**

- 内核不超过 1.5 万行（不含测试）。任何模块不超过 1.5 万行，超过即拆分或删减。
- 根 `AGENTS.md` 一页，每模块一页。写不下的规则变成类型，或删掉。
- 结构检查只有两个：依赖方向，行数上限。

**测试。** 推导器靠输入样例。内核为五类不变量写测试：数据不可逆、生效与判分的确定性、并发、安全与用途边界、危机转介。其余默认不写。 测试代码占全部代码不超过 10%，含夹具、测试基础设施和生成器内嵌样例；统计口径与检查入口见实现契约 §5。

## 9. 验收

**场景与功能共同验收。** §2 每个场景、§3 每条承诺、产品规格 D01–D10 的反例和 F01–F73 每项纳入范围，都须有对应的真实行为证据。原 11 个场景不能替代完整产品交付。

**变更局部性**

| 变更 | 触碰范围 |
|---|---|
| 加一条人和 AI 都能用的命令 | 1 个文件 |
| 给已有槽位加一个推导器 | 1 个文件加样例 |
| 加一个视图 | 1 个推导器文件，可能加 1 个块 |
| 加一门学科 | 0 行代码 |
| 换某个推导器用的模型 | 1 处配置 |
| 加一种后台行为 | 1 份工作单定义加提示词 |
| 加一种学习活动形态 | 1 个事实类型、1 个评估推导器、1 个块 |

**内核反证**

| 情形 | 必须观察到 |
|---|---|
| 更正已提交，重算未发生，旧候选到达 | 拒绝生效 |
| 更正与候选生效同时发生 | 有确定先后，没有空隙 |
| 证据持续到达，同时有一个长推导在跑 | 能按截至某时刻生效并标明新鲜度，不会永远重算 |
| 推导中途读了新材料，该材料随后被更正 | 新读取已在清单内，候选被拒绝 |
| 模型调用已扣费，结果在返回途中丢失 | 按提供方能力核对；无法确认保留 unknown，不盲目重付，不假称提供方保证恰好一次 |
| 同一命令重发；两次内容相同的真实作答 | 前者生效一次，后者都记录 |
| 判分成功，掌握度推导失败 | 判分保持生效，掌握度显示待更新 |
| 重新抽取一份学习者改过的材料 | 学习者的修改保留，差异成为提议 |
| 停用一个推导器 | 它产出的推导仍可读，槽位标明当前无可用方法 |
| 所有模型服务不可用 | 「今天」仍有内容，已有判断仍可读 |

## 10. 不做

- 多租户服务、家长端、教师端、同伴之外的第二个对话 agent。
- 公开插件市场；第三方代码的运行。
- 身体与睡眠数据。
- 原生应用、完整离线推理。
- 微服务、全量事件溯源、通用工作流编辑器。
- 为单个想法建专属队列、路由器、分类器或审查链。
- 被动监听、群聊监控、未经本人决定自动联系第三方；缺乏依据的数值提分、按分钟保证收益和因果价值排行榜。按需语音、教同伴和活动时长估计按产品规格 D09 做。
- 旧系统行为的兼容。旧系统的八项「承重能力」不作为义务继承；其中仍有价值的性质已经是本文的承诺：判断不可变只能被取代（§4.1）、提议加确认加撤销（§4.2）、确定性兜底（§3 第 7 条）、运行与花费记录（§5）、统计信号保留（§6）。

## 11. 风险与推翻条件

- **内核是单点。** 生效协议、过时判定、通用存储上的查询都在这里。内核接口在冻结之前，要用 §2.1 到 §2.3 这条链完整走通，并且做两种不同的设计来比较。
- **传递过时的代价。** 掌握度依赖大量判分，安排依赖大量掌握度。截至引用是为此设的，但它的粒度选错会导致要么漏判要么重算风暴。需要用接近真实的数据量尽早测。
- **采纳的边界。** 什么该是事实、什么该留作推导，会反复遇到。判据是：它是否需要独立身份，是否会被人直接修改。如果这条判据经常给不出答案，模型需要修正。
- **第二系统效应。** 防线是行数上限，以及「新能力必须是四种可写的东西之一」。
- **便宜模型的假设未经验证。**

**出现以下任一情况，推翻 §4 重新设计，而不是加例外：**

- §2 或产品规格中的能力无法用三种领域数据和四种模块构件表达，需要增加另一类领域真相。永久删除仅按 ADR-0008 作存储生命周期例外，不能借此开放任意模块改写历史。
- 内核在 1.5 万行内写不下。
- 加入 §7 推迟的设施时需要改模块代码。
- 便宜模型在给定骨架和样例的条件下，仍然不能稳定地独立完成推导器任务。
