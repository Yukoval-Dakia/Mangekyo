# 内核只有事实、推导、命令三种数据

系统里的一切要么是发生过的事实，要么是带输入清单的推导，要么是写入事实的命令。推导生效时由内核核对其输入仍然有效；事实被更正后，依赖它的推导自动过时。模块不建表，也不实现一致性协议。

选它是因为更正传播、可解释、可回溯、换方法、任意位置执行计算，在这个模型里是同一个机制的不同用法，而旧系统和早先设计都要为每一项各建一套。

放弃的方案：按领域分表、各领域自行实现接纳与失效（早先设计）。它更贴近常规做法，查询也更直接，但同一套易错的锁序与守卫要写多遍，且每个领域的开发者都得懂它。

后果：内核是单点，通用存储的查询性能和传递过时的代价由内核承担。推翻条件见 PRD §11。
